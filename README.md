# Вишлист

Одностраничное приложение-вишлист: автор ведёт список желаний, а друзья смотрят его,
понимают, что именно нужно, и могут «забить» подарок, чтобы не дарить одно и то же.
Всё — один файл `index.html` (стили и скрипт внутри, `supabase-js` с CDN).

## Что умеет

- **Добавление айтема** — вручную или из ссылки. Парсинг ссылки гибридный: если у
  сайта есть Open Graph-теги, подставляются название/картинка/цена/магазин; если
  нет — подставляется хотя бы домен, остальное дозаполняется вручную.
- **Оценка звёздами** (0–5, клик по звезде; повторный клик сбрасывает в 0) и
  **заметка автора** — почему хочу / зачем / детали. Статус зависит от оценки:
  5 — «очень хочу», 4 — «сильно хочу», 3 — «хочу», 1–2 — «если что».
- **Карточка раскрывается** по клику: крупная картинка, заметка, цена и кнопка
  «Открыть в магазине» — не нужно уходить со страницы, чтобы всё рассмотреть.
- **Картинка** — загрузка файла (хранится в Supabase Storage) или ссылка; есть
  превью и кнопка «Убрать».
- **Категории** — поле с подсказками: уже использованные категории предлагаются
  списком, печатать заново не нужно.
- **Категории, фильтр, сортировка (звёзды/дата), поиск.**
- **Брони подарков**: авторизованный друг «забивает» подарок, другие видят
  «Забито: <имя>», а автор брони не видит (сюрприз сохраняется).
- **Отметка «Подарено»**: автор списка отмечает вручённый подарок — карточка
  приглушается и получает зелёную метку, бронировать её больше нельзя. Отметку
  можно снять кнопкой «Вернуть в список».
- **Роли**: админ (создаёт/правит/удаляет айтемы), друг (бронь + чтение), гость
  (только чтение).
- **Тёмная тема по умолчанию** + переключатель на светлую.

## Быстрый старт (демо-режим)

Просто откройте `index.html` в браузере. Пока не заданы ключи Supabase, приложение
работает в **демо-режиме**: данные хранятся в `localStorage` этого браузера, вы
считаетесь админом. Удобно потрогать интерфейс до настройки бэкенда.

## Настройка общего списка (Supabase)

Нужно один раз, чтобы данные были общими для всех. Всё, что нужно, лежит в репозитории:

- `supabase/schema.sql` — схема БД, Storage и правила доступа;
- `supabase/functions/parse-link/index.ts` — код Edge Function для парсинга ссылок.

Шаги:

1. Создайте проект на [supabase.com](https://supabase.com) (бесплатный тариф).
2. Откройте **Project Settings** (шестерёнка внизу слева) → **API Keys** и скопируйте
   `publishable key` (начинается с `sb_publishable_`; в старом интерфейсе это
   `anon public` — длинная строка `eyJ...`) в `SUPABASE_CONFIG.key` в начале скрипта
   `index.html`. `SUPABASE_CONFIG.url` — это `https://<project-ref>.supabase.co`
   (не адрес панели `supabase.com/dashboard/...`).
   Ключ `secret` / `service_role` вставлять **нельзя** — он обходит все правила доступа.
3. Выполните `supabase/schema.sql` в SQL Editor — создадутся таблицы
   `items`/`reservations`/`profiles`, публичный bucket `wishlist-images` для картинок,
   RLS-политики и триггер создания профиля.
4. Разверните Edge Function `parse-link`:
   ```bash
   npx supabase link --project-ref <project-ref>
   npx supabase functions deploy parse-link --no-verify-jwt
   ```
5. Включите вход по magic link (Authentication → Providers → Email) и добавьте адрес
   сайта в Redirect URLs.
6. Войдите и сделайте себя админом:
   `update profiles set is_admin = true where user_id = '<ваш uid>';`
7. Опубликуйте сайт (см. ниже).

## Деплой на GitHub Pages

1. Загрузите `index.html` в корень репозитория GitHub.
2. Settings → Pages → Deploy from branch → `main` / `root`.
3. Через минуту страница будет доступна по ссылке вида
   `https://<user>.github.io/<repo>/`.

> Имя `index.html` обязательно: GitHub Pages ищет файл с таким именем в корне.
> Если его нет, вместо приложения откроется `README.md`.

## Брони подарков

Автор вишлиста **не видит, кто** забронировал подарок — иначе сюрприз ломается.
Но он видит, **что** подарок уже занят: на карточке появляется синяя метка
«Забронировано». Другие дарители видят «Забито: Имя», а свой подарок могут отменить.

Чтобы метка работала, в базе нужна функция `public.reserved_item_ids()`: она отдаёт
админу только id занятых айтемов, без имён. Она уже есть в `supabase/schema.sql`.

**Если база настроена раньше**, выполните один раз
`supabase/patch-01-admin-sees-reserved.sql` в SQL Editor. Без патча всё остальное
работает, просто метки не будет.

## Отметка «Подарено»

Кнопка «Уже подарили» есть только у автора списка — на карточке и в раскрытом
просмотре. Она ставит в `items.gifted` флаг, карточка получает зелёную метку
«Подарено», а друзьям больше не предлагается бронь. Счётчик в шапке показывает,
сколько подарков уже вручено.

**Если база настроена раньше**, выполните один раз
`supabase/patch-02-gifted.sql` в SQL Editor (добавляет колонку `items.gifted`).
До патча добавление и правка айтемов продолжают работать — просто отметка
не сохраняется.

## Вход по почте: лимит писем

Вход сделан по magic link: вводишь email → приходит письмо → кликаешь ссылку →
оказываешься в системе. Пароля нет.

**Важно:** пока не подключён свой SMTP, Supabase отправляет письма через встроенную
почту с жёстким лимитом — примерно **2 письма в час на весь проект**. При превышении
API отвечает `429 over_email_send_rate_limit`, и письмо не уходит. Кроме того, такие
письма часто попадают в «Спам», особенно на Яндекс.Почту.

Что делать:

- Подождать час и попробовать снова.
- Проверить папку «Спам».
- Подключить свой SMTP (Resend, Brevo, Mailgun — есть бесплатные тарифы):
  Supabase → **Authentication → Emails → SMTP Settings**. Это снимает лимит и
  сильно улучшает доставляемость.

Приложение теперь показывает реальную причину: если письмо не ушло, под кнопкой
появится текст ошибки, а не ложное «Письмо отправлено».

## Тесты

Логика приложения покрыта встроенным мини-харнессом (без зависимостей).

- В браузере: откройте `index.html?test=1` — результат покажется на странице и в
  консоли.
- В терминале (нужен Node):
  `node ../.koda/sdd/wishlist/run-tests.mjs`
  (раннер извлекает скрипт из `index.html`, выполняет в песочнице и печатает
  `TESTS OK` / `TESTS FAILED`).
